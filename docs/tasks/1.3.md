# 1.3 — Invariant guards and Lua test harness
Goal: cheap automatic checks for CLAUDE.md's non-negotiable rules, plus the lupa helper later Lua tasks use.
Owns: `tests/unit/test_invariants.py`, `tests/lua/__init__.py`, `tests/lua/lua_helpers.py`, `tests/lua/test_lua_syntax.py`.
Read-only context: `agent/core/*.py`, `tests/unit/test_core_contract.py`, `CLAUDE.md`, `docs/PLAN.md` section 3 (design principles).
Do not touch: anything else (no `agent/` edits, no `upstream/`).

## Behaviour
1. `test_invariants.py`:
   - No dataclass field in `agent.core.models` or `agent.core.ops` (including nested) is named index/idx/id-like except `Plan.id`/`OpResult.index`/`Marker.number`/`FxInfo`/`param` semantics: write an explicit allow-list and fail on anything else containing "index" or "idx".
   - Every op in `ops.OPS` lists its object-id fields in `targets` (or has a custom `validate` for set_ext_state) and rejects an int or "3" in each.
   - Lua deny-list: scan every `lua/agent/*.lua` (the folder may be empty now; the test must still pass then) and fail on any of: `DeleteTrack(`, `DeleteTrackMediaItem`, `DeleteTakeFromItem`, `os.remove`, `os.execute`, `io.popen`, `io.open(` with a write mode ("w", "a", "wb"), `reaper.ExecProcess`, `SaveProject`, `Main_SaveProject`. `DeleteEnvelopePointRange` / `DeleteEnvelopePointRangeEx` are allowed ONLY in `lua/agent/ops_fx.lua`. Use a regex scan that ignores `--` comment lines.
   - Every Lua op handler must be referenced in a per-op list: for each op type in `ops.OPS` a handler name `op_<type>` must exist in some `lua/agent/ops_*.lua` once those files exist; until `lua/agent/ops_*.lua` exists the test is skipped with a clear reason.
   - Every `tests/unit/test_core_contract.py::EXAMPLES` entry type is covered (the vocabulary test already exists; just assert OPS and EXAMPLES agree by importing it).
2. `tests/lua/lua_helpers.py`: `load_lua(path, reaper=None)` that runs a file inside `lupa.LuaRuntime(unpack_returned_tuples=True)` with an optional fake `reaper` table (a Python object exposing `reaper` as a Lua table of callables), returning the module table the file returns; plus `syntax_check(path)` using `loadfile`/`load` without executing.
3. `tests/lua/test_lua_syntax.py`: parametrised over `lua/agent/*.lua` (skip with a reason if none) and also over `upstream/bridge/automation.lua` as a sanity check of the helper. Include one self-test of `lua_helpers` on a tiny inline Lua snippet in a tmp file so the harness is tested before any real Lua exists.
4. A test file `tests/unit/test_fake_roundtrip.py` that, for every op in `ops.OPS`, applies a valid example (build them from `tests/unit/test_core_contract.py::EXAMPLES`, adapting GUIDs to the objects in `tests.unit.factories.make_snapshot()`; give examples that need lanes a track already in fixed-lane mode via an earlier op in the same plan) through `agent.bridge_client.fake.FakeBridge`, then `undo()`, and asserts `snapshot_hash` equals the original. Import `FakeBridge` inside the test and `pytest.skip("fake bridge not merged yet")` on ImportError (task 1.1 is writing it in parallel).

## Done when
`uv run pytest tests/unit/test_invariants.py tests/lua -q` passes (round-trip test may skip), `uv run ruff check agent tests` and `ruff format --check` clean. Stdlib + lupa only.
Report (under 150 words): files changed, test result, assumptions, open issues.
