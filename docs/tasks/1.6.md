# 1.6 — Lua op handlers: take/lane/region/ext and FX/envelope groups (live REAPER)
Goal: implement the remaining 11 ops in Lua so every op in `agent/core/ops.py` has an `op_<type>` handler, each verified by an apply -> undo -> identical-snapshot integration test on a live REAPER.
Owns: `lua/agent/ops_take.lua`, `lua/agent/ops_fx.lua`, `tests/integration/test_take_ops_roundtrip.py`, `tests/integration/test_fx_ops_roundtrip.py`. You may make minimal edits to `lua/agent/snapshot.lua` ONLY if a snapshot field needed to verify an op is wrong or missing (say so in your report).
Read-only context: `lua/agent/ops_track.lua` (the pattern to copy), `lua/agent/apply_plan.lua` (state object `S`: `S.track/item/take(id)`, `S.save_original(kind,obj,name,value)`, `S.define_ref`, `S.refs`), `lua/agent/util.lua`, `lua/agent/snapshot.lua`, `agent/core/ops.py` (exact fields and validation), `docs/tasks/1.1.md` (the semantics each op must have; the Lua must match it), `tests/integration/conftest.py` + `test_track_ops_roundtrip.py` (how to test live), `CLAUDE.md`.
Do not touch: other files, `upstream/`, `agent/core/*`.

## Handlers
Each is `M.op_<type> = function(op, S)` in a file returning `function(ctx, U) -> M` (see ops_track.lua). Raise `error("message")` on failure; return an optional data table.
- ops_take.lua: `op_set_take_name` (orig_name saved on the take), `op_set_track_lane_mode` (I_FREEMODE: normal 0, free 1, fixed_lanes 2; orig_lane_mode), `op_set_item_lane` (I_FIXEDLANE; error unless the track is in fixed_lanes mode; orig_lane), `op_set_lane_name` (P_LANENAME:n; pad lanes if needed), `op_add_region` (define `ref:<alias>` -> the new region's GUID via MARKER_GUID), `op_set_region` (only provided fields change; orig saved once in PROJECT ext as `orig_region:<guid>` JSON {name,start,end,color}; error if target is a plain marker or end<=start), `op_set_ext_state` (scope track/item/take via `U.ext_write`, key stored WITHOUT the `reaper_agent:` prefix; scope project via `SetProjExtState(0, "reaper_agent", key, value)`).
- ops_fx.lua: `op_set_fx_param` (find the FX by GUID on the track, `TrackFX_SetParamNormalized`; error if the FX GUID is not on that track; save the old value once as track ext `orig_fxparam:<fxguid>:<param>`; return {before=, after=}), `op_ensure_fx_envelope` (`GetFXEnvelope(tr, fx_index, param, true)`; make it active and visible; no-op if present), `op_clear_envelope_range` (error if the envelope does not exist; `DeleteEnvelopePointRangeEx(env, -1, start, end)`; deleting points inside the planned range is allowed ONLY in this file), `op_insert_envelope_points` (error if the envelope does not exist; `InsertEnvelopePointEx(..., noSort=true)` for each point then one `Envelope_SortPointsEx`; shapes linear 0, square 1, slow 2, fast_start 3, fast_end 4, bezier 5; values are in the envelope's own scale).
Verify every REAPER API name and attribute string against the current ReaScript documentation (https://www.reaper.fm/sdk/reascript/reascripthelp.html) or by probing `reaper.APIExists` in a tiny test; CLAUDE.md says do not trust memory, especially for REAPER 7 fixed lanes. If an API does not behave as the docs say, find out why on the live system and note it in your report.
Never call Delete* functions other than the envelope range delete above (a test in `tests/unit/test_invariants.py` scans for them); no file writes, no `os.execute`.
