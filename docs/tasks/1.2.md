## Behaviour
- Newline-delimited JSON-RPC 2.0 over stdin/stdout, stdlib only. Methods: `initialize` (echo the client's protocolVersion if it is one of 2025-06-18, 2025-03-26, 2024-11-05, else answer 2025-06-18; capabilities {"tools": {}}; serverInfo name "reaper-agent"), `notifications/initialized` (no reply), `ping`, `tools/list`, `tools/call`. Unknown method -> error -32601; bad params -> -32602. Tool failures are results with `isError: true` and a short text message, never protocol errors. Log to stderr only; stdout is protocol only.
- `build_server(bridge, store, profile="core") -> Server` with `handle_message(dict) -> dict | None` and `serve(stdin, stdout)`. `main()` reads env `REAPER_AGENT_PROFILE` (core|full, default core) and creates the real bridge lazily via `agent.bridge_client.daemon.DaemonBridge()` (module not written yet: import inside `main()` and fail with a clear message if missing).
- Tools (descriptions under 200 characters each, JSON schema inputs):
  `get_project_overview` (project info, track/item/region counts, snapshot hash, bridge status),
  `get_snapshot(section, limit?, offset?)` (section from `models.SECTIONS`; page tracks/items with default limit 100),
  `plan_rename_track(track, new_name)` (builds a plan with `store.build_plan`, returns plan id, summary, base hash and the expected changes as readable text via `agent.core.diff.format_changes` when available, else raw dicts),
  `apply_plan(plan_id, dry_run=false)`, `discard_plan(plan_id)`, `undo_last_plan()`.
  `full` profile adds `list_plans` and `get_plan(plan_id)`. Both profiles must stay under 30 tools.
- Mutating tools only go through `store.build_plan` / `store.apply_stored_plan` / `store.undo_last`. `StalePlanError` becomes an error result that says to re-plan. Input GUIDs are validated with `models.is_guid`; integer track indices are rejected with a clear message.
